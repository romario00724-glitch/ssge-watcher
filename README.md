# Монітор ss.ge → Telegram

Кожні ~10 хвилин перевіряє пошук на ss.ge (лише оголошення від власників) і надсилає в Telegram тільки **нові** оголошення: фото, ціна, район, телефон, посилання. Агентів, які прикидаються власниками, позначає ⚠️.

Це близнюк [myhome-watcher](https://github.com/romario00724-glitch/myhome-watcher): той самий код, ті самі повідомлення й позначки, тільки для ss.ge. Шле в ту саму робочу групу, але **окремим ботом** — за іменем бота видно, з якого сайту оголошення.

Файли: `watcher.py` — скрипт, `searches.txt` — посилання на пошук, `requirements.txt` — залежності, `.github/workflows/watch.yml` — автозапуск на GitHub.

---

## 1. Telegram-бот (5 хвилин)

1. У Telegram відкрийте **@BotFather** → `/newbot` → придумайте назву (наприклад, «SS.ge монітор»). Він дасть **токен** виду `7123456789:AAH...`.
2. Додайте нового бота в ту саму групу, куди пише бот myhome.
3. **chat_id** — той самий, що в myhome-watcher (у групи він від'ємний, з мінусом).
   Або `python watcher.py --chat-id`, коли токен уже вказаний: напишіть у групі будь-що й запустіть.
   Кілька чатів — через кому: `123456789,-100987654321`.

## 2. Посилання з ss.ge

1. На home.ss.ge оберіть: **Аренда** → **Квартира** → **Батуми**, за бажанням район, ціну, кімнати.
2. Застосуйте фільтри й скопіюйте адресу з адресного рядка. У ній мають бути `/l/Квартира/Аренда` (або `bina/qiravdeba`, `Flat/For-Rent` — підходить будь-яка мова сайту) і `cityIdList=`.
3. Вставте в `searches.txt`. Можна кілька рядків, наприклад оренда й продаж окремо:
   ```
   Оренда | https://home.ss.ge/ru/недвижимость/l/Квартира/Аренда?cityIdList=96
   Продаж | https://home.ss.ge/ru/недвижимость/l/Квартира/Продается?cityIdList=96
   ```

Фільтр «От собственника» і сортування «за датою» скрипт додає сам — без сортування згори стоять старі VIP-оголошення, і нові тонуть. Новий рядок у `searches.txt` при першому запуску тихо «запам'ятовує» поточні оголошення, щоб не засипати чат старими.

## 3а. Перевірка на своєму комп'ютері

Потрібен Python 3.10+ (python.org). У папці з файлами:

```
pip install -r requirements.txt
```

Токен і chat_id або впишіть у `telegram.json` поруч зі скриптом (`{"token": "...", "chat_id": "..."}`), або задайте в терміналі:

- Mac/Linux: `export TELEGRAM_BOT_TOKEN="..."` і `export TELEGRAM_CHAT_ID="..."`
- Windows (PowerShell): `$env:TELEGRAM_BOT_TOKEN="..."` і `$env:TELEGRAM_CHAT_ID="..."`

Далі:

```
python watcher.py --test    # покаже 3 свіжі оголошення і надішле 1 тестове в Telegram
python watcher.py           # стежить, поки комп'ютер увімкнений (Ctrl+C — зупинити)
```

Без токена обидві команди нічого не шлють — просто друкують оголошення в консоль.

У `--test` перевірте два рядки:
- «міста: …» — там має бути Батуми;
- «Кількість оголошень автора на сайті: N (поле «applicationCount») ✅». Якщо замість цього написано «не знайдено», запустіть `python watcher.py --dump` і гляньте файли `dump_list.json` і `dump_detail.json` — по них видно, як сайт тепер називає це поле.

**Не запускайте бота на комп'ютері одночасно з GitHub** — у двох копій різні `state.json`, і ті самі оголошення прийдуть у групу двічі.

## 3б. Цілодобово й безкоштовно на GitHub

1. Публічний репозиторій `ssge-watcher` з усіма файлами цієї папки.
2. **Settings → Secrets and variables → Actions → New repository secret**: `TELEGRAM_BOT_TOKEN` (токен **нового** бота) і `TELEGRAM_CHAT_ID` (та сама група, що в myhome).
3. **Actions → ssge-watcher → Run workflow**. Перший запуск надішле «✅ Стежу за пошуком…», далі нові оголошення приходитимуть самі.

Нотатки:
- У публічному репозиторії запуски безкоштовні без обмежень. Видно в ньому лише код, посилання на пошук і `state.json` (номери вже побачених оголошень; телефони там лише як нечитабельні відбитки). Токен захований у Secrets.
- Розклад GitHub (`cron:`) на практиці пропускає майже всі слоти — тому запускає бота зовнішній будильник, див. розділ «Хто насправді запускає бота».
- Змінити пошук можна прямо на сайті GitHub: відкрийте `searches.txt` → олівець → збережіть.

## Переклад

ss.ge сам віддає опис російською (сайт перекладає оголошення на три мови), тому ключ OpenAI цьому боту **не потрібен**. Якщо колись сайт не дасть російського тексту, а в секретах буде `OPENAI_API_KEY`, бот перекладе грузинський чи англійський опис сам — так само, як myhome-watcher. Вимкнути — `TRANSLATE_ALERTS = False` угорі `watcher.py`.

## Хто насправді запускає бота

Так само, як у myhome-watcher: розклад GitHub (`cron:` у `watch.yml`) спрацьовує рідко й нерегулярно, тому справжній будильник — зовнішній і безплатний **cron-job.org**. Він щодесять хвилин сам натискає «Run workflow» через GitHub API.

```
cron-job.org ──► GitHub Actions ──► ss.ge ──► Telegram
 :05 :15 :25…     ~30 секунд        читає    картка в групу
```

Будильник myhome спрацьовує о :00, :10, :20…, а цей — о **:05, :15, :25…**, щоб боти не працювали одночасно. `cron:` у `watch.yml` лишився як запасний (о :08, :18…). Ознака, що все працює як треба: в **Actions** у кожного запуску написано `workflow_dispatch`, а не `schedule`.

### Як налаштований будильник

Завдання `ssge-watcher` на [console.cron-job.org](https://console.cron-job.org/jobs) — клон завдання `myhome-watcher`, у якого змінено лише адресу й хвилини:

| Поле | Значення |
|---|---|
| URL | `https://api.github.com/repos/romario00724-glitch/ssge-watcher/actions/workflows/watch.yml/dispatches` |
| Розклад | Custom: хвилини `5,15,25,35,45,55`, кожної години (`5-55/10 * * * *`) |
| Request method | `POST` |
| Request body | `{"ref":"main"}` |
| Заголовки | ті самі три, що в myhome: `Accept`, `Authorization: Bearer github_pat_…`, `X-GitHub-Api-Version` |

Ключ доступу — той самий fine-grained токен, що й у myhome, з доступом до обох репозиторіїв (`Actions: Read and write`). Тому й дата, коли він спливе, спільна: **28 вересня 2027**. Тоді замовкнуть обидва боти, прийде лист від cron-job.org. Лікування — новий токен з доступом до обох репозиторіїв, підставити в обидва завдання на cron-job.org.

### Як перевірити, що бот живий

Відкрити [Actions репозиторію](https://github.com/romario00724-glitch/ssge-watcher/actions): якщо верхній запуск свіжий (не старший за ~15 хвилин) і зелений — усе гаразд. `нових оголошень немає` у логу — нормальна відповідь, а не поломка.

## Що означають позначки

- **✅ У автора 1 оголошення на ss.ge** / **⚠️ У автора 25 оголошень на ss.ge** — скільки оголошень у цього автора на всьому сайті (те саме число, що ss.ge показує в «Все объявления пользователя», працює з першого дня). З `AGENT_THRESHOLD` і більше — це агент під виглядом власника або інвестор із кількома квартирами (теж цікавий контакт).
- **⚠️ Цей автор або телефон уже трапився в N оголошеннях** — власна база скрипта. З'являється, коли вона знає більше за сайт (наприклад, той самий телефон на кількох акаунтах).
- **⚠️ В описі згадується агенція або комісія.**
- **✍️ Пише, що без посередників** — лише підказка, агенти теж так пишуть.
- Оголошення, автору яких ss.ge сам ставить значок **«Агент»**, бот не надсилає зовсім. Фільтр ss.ge «От собственника» відсіює лише компанії, а приватних агентів пропускає — без цього в групу йшли б і вони.
- **🕒 07.10.2024 18:28, оновлено 30.09 14:20** — оголошення подане давно, а власник його щойно «підняв». На ss.ge таке буває часто; рік пишеться, коли він не поточний.

Телефон ss.ge віддає повністю.

## Налаштування (вгорі `watcher.py`)

- `AGENT_THRESHOLD = 3` — з якої кількості оголошень автора ставити ⚠️.
- `SKIP_SUSPECTED_AGENTS = False` — `True`, щоб таких узагалі не надсилати (рахується більше з двох чисел: на сайті чи в базі скрипта).
- `SKIP_SITE_AGENTS = True` — не надсилати оголошення, автору яких ss.ge ставить значок «Агент» (`False` — надсилати й такі).
- `LANG = "ru"` — мова назв, описів і посилань (`ru` / `en` / `ka`).
- `MAX_ALERTS_PER_RUN = 25` — максимум повідомлень за одну перевірку.

## Якщо щось не так

- **HTTP 403 / «сторінка перевірки від Cloudflare»** — ss.ge прийняв запит за бота. Перевірте, що встановлено `curl_cffi`. Якщо на GitHub це повторюється годину поспіль, бот сам напише в Telegram.
- **«немає фільтра міста»** — у посиланні немає `cityIdList=`. Застосуйте фільтри на сайті ще раз і скопіюйте адресу.
- **У Actions помилка push (403)** — Settings → Actions → General → Workflow permissions → **Read and write**.
- **Почати з нуля** — `python watcher.py --reset` (або видаліть `state.json` на GitHub).
- Скрипт працює через внутрішній API сайту: бере гостьовий ключ з головної сторінки ss.ge (так само робить браузер), а пошук, ім'я, телефон, лічильник оголошень автора й значок «Агент» — з `api-gateway.ss.ge`. Сторінки окремих оголошень ss.ge серверам GitHub не віддає, тому бот їх не відкриває. Якщо ss.ge це змінить, скрипт доведеться підправити.
